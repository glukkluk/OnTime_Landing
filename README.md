# OnTime · лендінг

Окремий маркетинговий сайт персонального планувальника OnTime.
Мета — розповісти про продукт і перевести відвідувача до реєстрації у Django-застосунку.

## Про продукт

OnTime об'єднує календар із повторюваними подіями, категорії, завдання з пріоритетами
та дедлайнами, нагадування всередині застосунку й особистий дашборд.
Автопланування підбирає вільні проміжки з урахуванням робочих годин, подій та буферів.
Вільні завдання можна підібрати під доступний час.

## Архітектура

За підходом із прикладу `landos-it21-bosco-main`: контент сторінки складається з блоків,
кожен із яких має власний frontend-рендерер і стилі.

```text
cms/       Payload 3 + Next.js + Neon PostgreSQL: адмінка й API контенту
frontend/  Vite + TypeScript: публічний лендінг
shared/    TypeScript-контракти публічного контенту
```

Потік: Neon → Payload → REST API → блоки Vite → перехід до Django.
Next.js обслуговує Payload; публічний лендінг збирає Vite.

Розвиваємо проєкт невеликими кроками за архітектурою прикладу.
Суттєві відхилення від нього спочатку погоджуємо з власником проєкту.

## Крок 1 — головний екран

Готові адаптивна шапка, hero, ілюстрація розкладу та посилання входу/реєстрації.
Контракт публічного контенту — у `shared/landing.ts`.

## Крок 2 — контент із CMS

- `Pages` → сторінка зі slug `home`: SEO-заголовок, SEO-опис і блок Hero.
- `Налаштування сайту`: назва, підпис шапки, назви кнопок та текст підвалу.
- `GET /api/landing`: об'єднує сторінку та налаштування у `{ page, site }`.
- Frontend завантажує контент через API, перевіряє його формат та екранує тексти.
  Є стан завантаження, повідомлення про помилку й повторна спроба.
- Читання публічне; редагування доступне авторизованим користувачам Payload.
- Ілюстрація розкладу — демонстраційний компонент frontend; адреси переходу до Django
  задаються через `VITE_APP_URL`.

### Запуск CMS із Neon

З каталогу `cms/`:

```sh
npm ci
# Лише якщо .env ще немає:
cp .env.example .env
```

У `cms/.env` задайте `DATABASE_URL` із Neon та `PAYLOAD_SECRET`.
Наявний `.env` уже містить підключення — повторно копіювати приклад не потрібно.
`FRONTEND_URL` — дозволені origins frontend через кому (типово localhost:5173 та localhost:4173).
Секрети й доступ до Neon використовує тільки CMS.

```sh
npm run dev
```

Адмінка: `http://localhost:3000/admin`. API: `http://localhost:3000/api/landing`.
Payload автоматично синхронізує схему Neon із конфігурацією колекцій і блоків
у режимі розробки (`npm run dev`), як у прикладі. Після зміни полів перезапустіть CMS
і відкрийте адмінку. Контент додавайте та редагуйте через Payload.

Після збереження змін в адмінці оновіть лендінг: він отримує актуальний контент без перезбірки.
SEO-теги оновлюються у браузері після запиту; статичний HTML зберігає початкові метадані OnTime.

## Крок 3 — можливості OnTime

У `Сторінки → home → Блоки сторінки` доступна секція **Можливості** після Hero:
заголовок, вступ, 1–6 карток і кнопка переходу до реєстрації. Картки можна редагувати
й переставляти в адмінці. Це маркетингові описи календаря, завдань і автопланування.
Секцію можна прибрати, залишивши лише Hero.

У підключеній Neon БД вже збережені три картки та назва OnTime.
Для іншої Neon БД створіть сторінку `home`, додайте блоки Hero та Можливості
й заповніть «Налаштування сайту» через адмінку.

## Крок 4 — як це працює

У `Сторінки → home → Блоки сторінки` додайте блок **Як це працює** після можливостей
(або одразу після Hero, якщо можливості приховані).
Він має початкові тексти про реєстрацію, додавання планів і автопланування.
В адмінці можна редагувати заголовок, вступ, 1–5 кроків та їхній порядок.
Нумерація кроків у лендінгу оновлюється автоматично.

Схему Neon синхронізує Payload у dev-режимі. Тексти зберігаються у CMS;
значення `defaultValue` заповнюють лише новий блок і не перезаписують редакторські зміни.

### Запуск frontend

З каталогу `frontend/`:

```sh
npm ci
cp .env.example .env.local
npm run dev
```

Відкрити адресу, яку виведе Vite (типово `http://localhost:5173`).
`VITE_CMS_URL` задає адресу Payload (типово `http://localhost:3000`). CMS має бути запущена.
`VITE_APP_URL` задає адресу Django (типово `http://localhost:8000`),
кнопки ведуть на `/register/` і `/login/`. Django потрібно запускати окремо.
Після зміни змінної перезапустіть Vite; для продакшну повторіть збірку.

Перевірка TypeScript і production-збірка: `npm run build`.
Перегляд збірки: `npm run preview`.

Перевірки CMS (із `cms/`):

```sh
npm run generate:types
npx tsc --noEmit
npm run lint
npm run test:int -- tests/int/landing.int.spec.ts
```

Тест контракту не підключається до БД.
